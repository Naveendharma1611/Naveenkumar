Module 1 — Introduction to HTML

What is HTML · How the web works · HTML, CSS & JavaScript · Tools · First page

▼

📜 What is HTML?

HTML (HyperText Markup Language) describes the structure and content of a web page using elements such as headings, paragraphs, links, images and forms. It is a markup language, not a programming language — it has no logic, loops or variables.

AspectDetail
Created byTim Berners-Lee, CERN, 1991
Current versionHTML5 — a "living standard" maintained by WHATWG
File extension.html (or .htm)
Runs inEvery web browser

🌍 How a Web Page Reaches You

  1. You type a URL or click a link.
  2. The browser sends an HTTP request to a web server.
  3. The server sends back HTML (plus CSS, JavaScript and images).
  4. The browser parses the HTML into the DOM (Document Object Model) and draws the page.

🧱 HTML, CSS and JavaScript

LanguageRoleAnalogy
HTMLStructure and contentThe walls and rooms of a house
CSSPresentation: colours, layout, fontsPaint and furniture
JavaScriptBehaviour: interactivity, dataElectricity and plumbing

🛠️ Tools You Need

  • A text editor: VS Code (with the Live Server extension) or any editor
  • A browser with DevTools (F12) to inspect elements
  • The W3C validator (validator.w3.org) to check your markup

👋 Your First Page

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, World!</h1>
  <p>This is my first web page.</p>
</body>
</html>

Save it as index.html and open it in a browser (double-click it, or right-click → Open with).

🏋️ Practice Questions

  1. Create index.html with your name as a heading and a short paragraph about yourself.
  2. Open any website, press F12 and find its <h1> element in DevTools.
  3. Explain the role of HTML, CSS and JavaScript in one sentence each.
  4. What does the browser build from HTML before drawing the page?
🎤 One-Line Interview AnswerHTML is the markup language that defines the structure of web pages; the browser parses it into the DOM, CSS styles it and JavaScript adds behaviour.

🦴 The Page Skeleton

<!DOCTYPE html>                <!-- this is an HTML5 document -->
<html lang="en">               <!-- root element; lang helps screen readers and SEO -->
<head>                         <!-- information ABOUT the page (not shown) -->
  <meta charset="UTF-8">       <!-- supports every character: ₹, é, தமிழ் -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Page title</title>    <!-- shown on the browser tab -->
</head>
<body>                         <!-- everything visible goes here -->
  ...
</body>
</html>

🪆 Nesting Rules

  • Close elements in the reverse order you opened them: <p><strong>Hi</strong></p> ✅, <p><strong>Hi</p></strong> ❌
  • Tag names are case-insensitive, but lowercase is the convention.
  • Always quote attribute values: class="card".
  • Extra spaces and line breaks in the source collapse into a single space on the page.

💭 Comments

<!-- This is a comment. The browser ignores it. -->
<!--
  Comments can span
  several lines.
-->
Anyone can read comments with View Source — never put passwords or secrets in them.

🏋️ Practice Questions

  1. Write the full HTML5 skeleton from memory.
  2. In <img src="cat.jpg" alt="A cat">, label the tag name, attribute names and attribute values.
  3. Fix the nesting: <p>Hello <em>world</p></em>.
  4. List five void elements.
  5. What goes wrong if you leave out <meta charset="UTF-8"> and write Tamil text?
🎤 One-Line Interview AnswerAn HTML document starts with <!DOCTYPE html> and has one <html> root containing <head> (metadata) and <body> (visible content); elements are made of tags, content and attributes.

<a href="tel:+919876543210">Call me</a>
<a href="files/resume.pdf" download>Download my resume</a>

<!-- Jump to a section on the same page -->
<a href="#contact">Go to contact</a>
<section id="contact">...</section>

🧭 A Navigation Menu

<nav>
  <ul>
    <li><a href="index.html">Home</a></li>
    <li><a href="projects.html">Projects</a></li>
    <li><a href="contact.html" aria-current="page">Contact</a></li>
  </ul>
</nav>
Add rel="noopener noreferrer" whenever you use target="_blank", and write meaningful link text — "Download the syllabus", not "click here".

🏋️ Practice Questions

  1. Build a 3-page site (Home, About, Contact) connected by a navigation menu.
  2. Add a "Back to top" link at the bottom of a long page.
  3. Create email and phone links.
  4. Link to a PDF so it downloads instead of opening.
  5. Explain the difference between about.html, /about.html and ../about.html.
🎤 One-Line Interview AnswerThe <a> element creates hyperlinks with href; paths can be absolute or relative, #id jumps within a page, and target="_blank" should be paired with rel="noopener".

Module 7 — Tables

table · tr · th · td · thead · tbody · tfoot · caption · colspan · rowspan

▼

📊 A Complete Table

<table>
  <caption>Semester marks</caption>
  <thead>
    <tr><th scope="col">Subject</th><th scope="col">Marks</th></tr>
  </thead>
  <tbody>
    <tr><td>Maths</td><td>92</td></tr>
    <tr><td>Physics</td><td>85</td></tr>
  </tbody>
  <tfoot>
    <tr><th scope="row">Total</th><td>177</td></tr>
  </tfoot>
</table>
ElementPurpose
<table>The table
<caption>Title of the table
<thead> / <tbody> / <tfoot>Header, body and footer row groups
<tr>A row
<th>Header cell (bold and centred by default)
<td>Data cell

🔀 Merging Cells

<table>
  <tr><th colspan="2">Name</th><th rowspan="2">Age</th></tr>
  <tr><th>First</th><th>Last</th></tr>
  <tr><td>Naveen</td><td>Kumar</td><td>21</td></tr>
</table>
  • colspan="2" stretches a cell across 2 columns.
  • rowspan="2" stretches a cell down 2 rows.
Use tables only for tabular data, never for page layout — use CSS Grid or Flexbox for layout.

🏋️ Practice Questions

  1. Create your class timetable (days × periods) with a caption.
  2. Build a price list with thead, tbody and a tfoot total.
  3. Recreate a mark sheet that uses both colspan and rowspan.
  4. Why should header cells use the scope attribute?
🎤 One-Line Interview AnswerTables are for tabular data; <th> marks headers (with scope for accessibility), thead/tbody/tfoot group rows, and colspan/rowspan merge cells.

📝 A Simple Form

<form action="/register" method="post">
  <label for="name">Full name</label>
  <input type="text" id="name" name="name" placeholder="Your name" required>

  <label for="email">Email</label>
  <input type="email" id="email" name="email" required>

  <label for="pwd">Password</label>
  <input type="password" id="pwd" name="password" minlength="8" required>

  <button type="submit">Register</button>
</form>
  • action is where the data is sent; method is how (GET or POST).
  • name is the key sent to the server; id connects the field to its <label for>.

▼

🏛️ Why Semantic HTML?

Semantic elements describe their meaning, not their look. They help screen readers, search engines and other developers understand the page.

<body>
  <header>
    <h1>My Blog</h1>
    <nav>...</nav>
  </header>

  <main>
    <article>
      <h2>Learning HTML</h2>
      <p>Published <time datetime="2026-09-25">25 Sep 2026</time></p>
      <section>
        <h3>Why HTML?</h3>
        <p>...</p>
      </section>
    </article>
    <aside>Related posts</aside>
  </main>

  <footer>
    <address>Contact: <a href="mailto:me@example.com">me@example.com</a></address>
  </footer>
</body>
ElementUse for
<header>Intro area: logo, title, navigation
<nav>Main navigation links
<main>The main content (one per page)
<article>Self-contained content: blog post, news story, product card
<section>A themed group of content, usually with a heading
<aside>Related side content: sidebar, tips
<footer>Closing information: copyright, contacts, links
<figure> / <figcaption>Image, chart or code with a caption
<time>Dates and times in machine-readable form

📦 Block vs Inline Elements

Block elementsInline elements
Start on a new line and take the full widthSit inside a line and take only the width they need
<div>, <p>, <h1>–<h6>, <ul>, <section><span>, <a>, <strong>, <img>, <code>
Can contain block and inline elementsShould contain only inline content

🧺 div and span

<div class="card">                                 <!-- generic block container -->
  <p>Price: <span class="price">₹499</span></p>    <!-- generic inline container -->
</div>
Reach for a semantic element first; use <div> and <span> only when nothing more specific fits.

🎁 Interactive Elements Without JavaScript

<details>
  <summary>What is HTML?</summary>
  <p>HTML is the markup language of the web.</p>
</details>

<dialog id="info" open>
  <p>This is a dialog box.</p>
</dialog>

🏋️ Practice Questions

  1. Convert a "div soup" layout (header, menu, content, sidebar, footer) into semantic elements.
  2. Build a blog post with article, section, time and figure.
  3. Make an FAQ page with details and summary.
  4. List 5 block elements and 5 inline elements.
🎤 One-Line Interview AnswerSemantic elements such as header, nav, main, article and footer describe meaning, which improves accessibility and SEO; div and span are generic containers for when nothing more specific fits.

⏱️ Loading Scripts: defer vs async

📈 SEO Basics in HTML

  • One clear <h1> per page and a logical heading order
  • A unique, descriptive <title> and meta description on every page
  • Meaningful link text and alt text on images
  • Semantic elements and fast-loading pages
  • Readable URLs: /html-course, not /page?id=123

Module 13 — Accessibility (a11y)

alt text · Labels · Headings · Landmarks · Keyboard · ARIA basics

▼

♿ Why Accessibility?

Accessible pages work for everyone — people using screen readers, only a keyboard, magnifiers or voice control. Many countries require it by law, and it also improves SEO.

✅ Accessibility Checklist

  • Every image has meaningful alt text (alt="" if decorative)
  • Every form field has a <label>
  • Headings follow order and describe their sections
  • Semantic landmarks: header, nav, main, footer
  • Everything clickable is a <button> or <a>, so it works with a keyboard
  • The page language is set: <html lang="en">
  • Strong colour contrast, and colour is never the only way information is shown
  • Captions on videos

⚖️ Bad vs Good

<!-- ❌ Bad -->
<div onclick="save()">Save</div>
<img src="logo.png">
<input placeholder="Email">

<!-- ✅ Good -->
<button type="button" onclick="save()">Save</button>
<img src="logo.png" alt="Naveen Tech logo">
<label for="email">Email</label> <input id="email" type="email">

🗣️ ARIA Basics

ARIA attributes give assistive technology extra information when HTML alone is not enough.

<button aria-label="Close menu">✕</button>
<nav aria-label="Breadcrumb">...</nav>
<div role="alert">Your changes were saved.</div>
<button aria-expanded="false" aria-controls="faq1">Show answer</button>
<a href="#main" class="skip-link">Skip to main content</a>
The first rule of ARIA: don't use ARIA if a native HTML element already does the job. A real <button> beats <div role="button">.

🏋️ Practice Questions

  1. Audit a page with Lighthouse (DevTools → Lighthouse → Accessibility) and fix three issues.
  2. Use a website with only the Tab, Shift+Tab and Enter keys.
  3. Add a "Skip to main content" link to your page.
  4. Rewrite a clickable div as a proper button.
🎤 One-Line Interview AnswerAccessibility means everyone can use the page: use semantic HTML, alt text, labels, logical headings and keyboard-friendly controls, and add ARIA only when native HTML is not enough.

Module 14 — HTML with CSS

Inline · Internal · External CSS · Selectors · Classes & ids

▼

🎨 Three Ways to Add CSS

<!-- 1. Inline: on one element (avoid) -->
<p style="color: green; font-size: 18px;">Inline style</p>

<!-- 2. Internal: inside the head of one page -->
<style>
  p { color: navy; }
</style>

<!-- 3. External: one file for the whole site (best) -->
<link rel="stylesheet" href="css/style.css">
MethodScopeWhen to use
InlineOne elementQuick tests only
InternalOne pageSingle-page demos
ExternalThe whole siteReal projects (cached and reusable)

🎯 Selectors Connect HTML and CSS

<h1 id="title">Welcome</h1>
<p class="intro">Hello!</p>
<p class="intro highlight">Learn HTML.</p>

<style>
  h1 { color: green; }              /* element selector */
  #title { text-align: center; }    /* id selector */
  .intro { font-size: 18px; }       /* class selector */
  .highlight { background: yellow; }
</style>
When rules conflict: inline style beats id, id beats class, and class beats element. With equal strength, the later rule wins.

🏋️ Practice Questions

  1. Style the same page in all three ways (inline, internal, external) and compare.
  2. Create a .card class and apply it to three different elements.
  3. Link one stylesheet to two HTML pages.
🎤 One-Line Interview AnswerCSS can be inline, internal or external — external stylesheets are preferred — and elements are targeted with element, class (.name) and id (#name) selectors.

🌳 The DOM: Reading and Changing the Page

<h2 id="greeting">Hello</h2>
<input id="name" placeholder="Your name">
<button id="btn" type="button">Greet me</button>
<ul id="list"></ul>

<script>
  const btn = document.getElementById("btn");
  btn.addEventListener("click", () => {
    const name = document.querySelector("#name").value;
    document.getElementById("greeting").textContent = `Hello, ${name}!`;

    const li = document.createElement("li");   // add a new element
    li.textContent = name;
    document.getElementById("list").append(li);
  });
</script>
MethodPurpose
getElementById("id")Find one element by its id
querySelector(".css") / querySelectorAll()Find elements with any CSS selector
element.textContent / .innerHTMLRead or change the content
element.classList.add("x")Add a CSS class
addEventListener("click", fn)Run code when an event happens
createElement() / append()Build and insert new elements

📍 Geolocation and Drag & Drop

<script>
  navigator.geolocation.getCurrentPosition(
    (pos) => console.log(pos.coords.latitude, pos.coords.longitude),
    () => console.log("Permission denied")
  );

<div draggable="true" id="item">Drag me</div>
<div id="box" style="border: 2px dashed; padding: 20px">Drop here</div>
<script>
  const box = document.getElementById("box");
  document.getElementById("item").addEventListener("dragstart", (e) => e.dataTransfer.setData("text", e.target.id));
  box.addEventListener("dragover", (e) => e.preventDefault());
  box.addEventListener("drop", (e) => box.append(document.getElementById(e.dataTransfer.getData("text"))));
</script>

Module 17 — Responsive HTML

Viewport · Fluid media · Responsive images · Mobile-first

▼

📱 The Viewport Meta Tag

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Without it, phones draw the page at desktop width (about 980px) and zoom out, so the text becomes tiny.

🌊 Fluid Images, Video and Tables

<style>
  img, video { max-width: 100%; height: auto; }   /* never wider than the screen */
  .table-wrap { overflow-x: auto; }               /* wide tables scroll sideways */
  .video { aspect-ratio: 16 / 9; }
  .video iframe { width: 100%; height: 100%; }
</style>

<div class="table-wrap"><table>...</table></div>
<div class="video"><iframe src="https://www.youtube.com/embed/VIDEO_ID" title="Demo"></iframe></div>

📐 Mobile-First Media Queries

<style>
  .grid { display: grid; gap: 16px; grid-template-columns: 1fr; }                 /* phones */
  @media (min-width: 768px)  { .grid { grid-template-columns: 1fr 1fr; } }         /* tablets */
  @media (min-width: 1024px) { .grid { grid-template-columns: repeat(3, 1fr); } }  /* laptops */
</style>
DeviceCommon width
Phone360–430px
Tablet768–1024px
Laptop / desktop1280px and wider
Test with DevTools device mode (Ctrl + Shift + M in Chrome and Edge) and on a real phone.

🏋️ Practice Questions

  1. Make an image gallery with 1 column on phones, 2 on tablets and 3 on laptops.
  2. Make a wide table scroll sideways on small screens.
  3. Embed a YouTube video that keeps a 16:9 shape at any width.
  4. Remove the viewport tag and compare the page on a phone.
🎤 One-Line Interview AnswerResponsive pages need the viewport meta tag, fluid images (max-width: 100%), responsive images with srcset or picture, and mobile-first CSS media queries.

Module 18 — Best Practices, Validation & Deployment

Clean code · Validation · Performance · Folder structure · Publishing

▼

🧹 Clean HTML Checklist

  • Lowercase tags and attributes, quoted values, consistent 2-space indentation
  • Close every non-void element and nest correctly
  • One <h1>, logical headings and semantic elements
  • alt on images and a <label> for every input
  • Separate files: HTML for structure, CSS for style, JavaScript for behaviour
  • Lowercase file names without spaces: about-me.html

🔍 Validate and Test

  • W3C Markup Validator: validator.w3.org
  • Lighthouse in DevTools: performance, accessibility and SEO scores
  • Test in Chrome, Firefox and Edge, and on a phone

⚡ Performance Tips

  • Compress images, use WebP/AVIF, and always set width and height
  • loading="lazy" on images and iframes further down the page
  • defer on scripts; stylesheets in the head
  • Minify CSS and JavaScript for production
