🌿 What is Django?

Django is a high-level Python web framework for building secure, maintainable websites quickly. It follows the "batteries included" idea: authentication, an admin panel, an ORM, forms, security protections and much more come built in.

AspectDetail
Created2003–2005 at the Lawrence Journal-World newspaper (Adrian Holovaty, Simon Willison)
Maintained byThe Django Software Foundation (open source, BSD licence)
LanguagePython
Used byInstagram, Pinterest, Mozilla, Disqus, Eventbrite, NASA
Motto"The web framework for perfectionists with deadlines"

⚡ Key Features

  • ORM — work with the database using Python classes instead of SQL
  • Admin panel — a complete content-management UI generated from your models
  • Authentication — users, passwords, sessions, permissions and groups
  • Forms — validation and HTML rendering
  • Security — protection against SQL injection, XSS, CSRF and clickjacking by default
  • Scalable ecosystem — Django REST Framework, Celery, Channels and thousands of packages

🏛️ MVT Architecture

PartRoleFile
ModelData and business rules; talks to the database through the ORMmodels.py
ViewReceives a request, runs the logic, returns a responseviews.py
TemplateThe HTML presentation with placeholderstemplates/*.html
URL dispatcherMaps each URL to a viewurls.py
MVT is Django's version of MVC: Django's view plays the role of the MVC controller, and the template is the MVC view.

🔄 The Request–Response Cycle

  1. The browser requests a URL, for example /post/hello-django/.
  2. Middleware processes the request (sessions, security, authentication).
  3. urls.py matches the URL and calls the right view.
  4. The view uses models (the ORM) to read or save data.
  5. The view renders a template with that data.
  6. An HttpResponse travels back through the middleware to the browser.

👁️ Your First Views

A view is a Python function that takes a request and returns a response.

# blog/views.py
from django.http import HttpResponse, JsonResponse


def home(request):
    return HttpResponse("<h1>Welcome to my blog</h1>")


def post_detail(request, post_id):
    return HttpResponse(f"You are reading post {post_id}")


def api_status(request):
    return JsonResponse({"status": "ok", "posts": 3})

🗺️ Mapping URLs to Views

# blog/urls.py
from django.urls import path

from . import views

app_name = "blog"          # namespace: use "blog:home" when reversing

urlpatterns = [
    path("", views.home, name="home"),
    path("posts/<int:post_id>/", views.post_detail, name="post_detail"),
    path("api/status/", views.api_status, name="api_status"),
]
# mysite/urls.py
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("blog.urls")),   # hand everything else to the blog app
]

🏷️ Named URLs and reverse()

Never hard-code URLs. Give each route a name and build URLs from it, so changing a path later updates every link.

from django.urls import reverse

reverse("blog:post_detail", args=[5])      # "/posts/5/"
reverse("blog:home")                       # "/"
<!-- In a template -->
<a href="{% url 'blog:post_detail' 5 %}">Read post 5</a>

A base template defines the page skeleton with {% block %} placeholders; child templates extend it and fill the blocks.

  <meta charset="UTF-8">

</head>
<body>

</html>

{% extends "base.html" %}
{% block title %}Blog{% endblock %}

🗃️ Defining a Model

A model is a Python class that describes a database table. Each attribute is a column.

# blog/models.py
from django.db import models
from django.urls import reverse


class Post(models.Model):
    class Status(models.TextChoices):
        DRAFT = "DR", "Draft"
        PUBLISHED = "PB", "Published"

    title = models.CharField(max_length=200)
    slug = models.SlugField(max_length=200, unique=True)
    body = models.TextField()
    status = models.CharField(max_length=2, choices=Status.choices, default=Status.DRAFT)
    views = models.PositiveIntegerField(default=0)
    created = models.DateTimeField(auto_now_add=True)   # set once, on creation
    updated = models.DateTimeField(auto_now=True)       # set on every save

    class Meta:
        ordering = ["-created"]                         # newest first by default

    def __str__(self):
        return self.title

    def get_absolute_url(self):
        return reverse("blog:post_detail", args=[self.slug])

🔁 Migrations

Migrations are Python files that record every change to your models, so the database schema can be created and updated step by step on any machine.

python manage.py makemigrations          # create migration files from model changes
python manage.py migrate                 # apply them to the database
python manage.py showmigrations          # list applied / pending migrations
python manage.py sqlmigrate blog 0001    # show the SQL a migration will run
Commit migration files to Git, and never edit the database tables by hand — always change the model and make a new migration.

💤 QuerySets are Lazy

Building a QuerySet doesn't touch the database. The query runs only when you use the results — loop over them, slice with a step, call list(), len(), count() or print them. That's why you can chain filters freely:

qs = Post.objects.filter(status="PB")        # no query yet
qs = qs.filter(views__gt=50).order_by("-created")
print(qs.query)                               # see the SQL
for post in qs:                               # the query runs here, once
    print(post.title)

# blog/models.py
from django.conf import settings
from django.db import models
from django.urls import reverse


class PostQuerySet(models.QuerySet):
    def published(self):
        return self.filter(status=Post.Status.PUBLISHED)


class Category(models.Model):
    name = models.CharField(max_length=100, unique=True)
    slug = models.SlugField(max_length=100, unique=True)

    class Meta:
        verbose_name_plural = "categories"
        ordering = ["name"]

    def __str__(self):
        return self.name


class Tag(models.Model):
    name = models.CharField(max_length=50, unique=True)

    def __str__(self):
        return self.name


class Post(models.Model):
    class Status(models.TextChoices):
        DRAFT = "DR", "Draft"
        PUBLISHED = "PB", "Published"

    title = models.CharField(max_length=200)
    slug = models.SlugField(max_length=200, unique=True)
    author = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE, related_name="posts")
    category = models.ForeignKey(Category, on_delete=models.SET_NULL, null=True, blank=True, related_name="posts")
    tags = models.ManyToManyField(Tag, blank=True, related_name="posts")
    body = models.TextField()
    image = models.ImageField(upload_to="posts/", blank=True)
    status = models.CharField(max_length=2, choices=Status.choices, default=Status.DRAFT)
    views = models.PositiveIntegerField(default=0)
    created = models.DateTimeField(auto_now_add=True)
    updated = models.DateTimeField(auto_now=True)

    objects = PostQuerySet.as_manager()      # adds Post.objects.published() (Module 9)

    class Meta:
        ordering = ["-created"]
        indexes = [models.Index(fields=["status", "-created"])]

    def __str__(self):
        return self.title

    def get_absolute_url(self):
        return reverse("blog:post_detail", args=[self.slug])


class Comment(models.Model):
    post = models.ForeignKey(Post, on_delete=models.CASCADE, related_name="comments")
    name = models.CharField(max_length=80)
    body = models.TextField()
    created = models.DateTimeField(auto_now_add=True)
    active = models.BooleanField(default=True)

    class Meta:
        ordering = ["created"]

    def __str__(self):
        return f"Comment by {self.name} on {self.post}"

🚀 The N+1 Problem: select_related and prefetch_related

# ❌ 1 query for posts + 1 query PER post for its author = N+1 queries
for post in Post.objects.all():
    print(post.author.username)

# ✅ select_related: follows ForeignKey / OneToOne with a SQL JOIN → 1 query
for post in Post.objects.select_related("author", "category"):
    print(post.author.username, post.category)

# ✅ prefetch_related: many-to-many and reverse relations → 1 extra query in total
for post in Post.objects.prefetch_related("tags", "comments"):
    print([tag.name for tag in post.tags.all()])

    subject = forms.CharField(max_length=150)
    message = forms.CharField(widget=forms.Textarea)

        name = self.cleaned_data["name"].strip()
        if len(name) < 2:
            raise forms.ValidationError("Please enter your full name.")
        return name

    def clean(self):                            # validate fields together
        cleaned = super().clean()
        if "http" in cleaned.get("subject", "") and "http" in cleaned.get("message", ""):
            raise forms.ValidationError("Links in both subject and message look like spam.")
        return cleaned

class PostDetailView(DetailView):
    template_name = "blog/post_detail.html"
    context_object_name = "post"

    def get_queryset(self):
        return Post.objects.published().select_related("author").prefetch_related("tags", "comments")

    def get_object(self, queryset=None):
        post = super().get_object(queryset)
        Post.objects.filter(pk=post.pk).update(views=F("views") + 1)
        return post

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["comment_form"] = CommentForm()
        return context

🧅 Middleware

Middleware wraps every request and response — like layers of an onion. Django's defaults handle security, sessions, CSRF, authentication and messages.

# blog/middleware.py
import time


class TimingMiddleware:
    """Adds an X-Response-Time header to every response."""

    def __init__(self, get_response):
        self.get_response = get_response          # runs once, at startup

    def __call__(self, request):
        start = time.perf_counter()               # before the view
        response = self.get_response(request)
        elapsed = (time.perf_counter() - start) * 1000
        response["X-Response-Time"] = f"{elapsed:.1f}ms"   # after the view
        return response
# In mysite/settings.py — order matters: requests run top to bottom, responses bottom to top

from datetime import timedelta

from django.core.management.base import BaseCommand
from django.utils import timezone

from blog.models import Post


class Command(BaseCommand):
    help = "Delete drafts older than N days"

    def add_arguments(self, parser):
        parser.add_argument("--days", type=int, default=30)

    def handle(self, *args, **options):
        cutoff = timezone.now() - timedelta(days=options["days"])
        deleted, _ = Post.objects.filter(status=Post.Status.DRAFT, created__lt=cutoff).delete()
        self.stdout.write(self.style.SUCCESS(f"Deleted {deleted} old draft(s)"))

QuestionShort answer
What is MVT?Model (data), View (logic), Template (presentation); Django's version of MVC
Project vs app?A project is the whole site and settings; an app is a reusable feature

null=True vs blank=True?Database may store NULL vs form may be left empty
What are migrations?Version-controlled files that change the database schema
select_related vs prefetch_related?JOIN for ForeignKey/OneToOne vs a separate query for many-to-many and reverse relations
get() vs filter()?One object (raises errors if 0 or many) vs a QuerySet of any size
Why are QuerySets lazy?They run SQL only when evaluated, so chaining is cheap
FBV vs CBV?Functions give full control; classes reuse generic CRUD behaviour and mixins

What are signals?Event hooks such as post_save that call receiver functions
How does CSRF protection work?A secret token in each POST form is checked by middleware

How do you make a custom user model?Subclass AbstractUser and set AUTH_USER_MODEL before the first migrate
