Module 1 — What Is Matplotlib?

Figure · Axes · Axis · pyplot · Object-oriented API

▼

🧭 What Matplotlib is and why it matters

Matplotlib is Python's foundational 2D plotting library. It renders line charts, bar charts, scatter plots, histograms, images and more, and it underlies higher-level tools such as pandas' .plot(), seaborn and many scientific visualization stacks. Learning Matplotlib's core model pays off even when you later reach for a higher-level library, because that library usually hands you back a Matplotlib Figure or Axes object to fine-tune.

🏗️ The Figure, Axes and Axis hierarchy

A Figure is the whole canvas or window — it can hold one or more plots. An Axes is a single plot area with its own data space, title, and x/y ranges; despite the name, one Axes is one chart, not an axis line. An Axis (singular) is the actual x or y number line on an Axes, with its own ticks, limits and label. Every Axes has exactly two Axis objects (x and y, or three for 3D), and a Figure can contain many Axes arranged in a grid.

import matplotlib.pyplot as plt

fig, ax = plt.subplots()          # fig: the whole canvas, ax: one plot area
print(type(fig), type(ax))
print(type(ax.xaxis), type(ax.yaxis))   # the Axis objects that belong to ax

⚖️ pyplot's state machine vs the object-oriented API

Matplotlib offers two ways to build the same chart. The pyplot API (plt.plot, plt.xlabel, ...) is a state machine: each call implicitly acts on "the current figure and axes," which is convenient for quick, single-plot scripts. The object-oriented (OO) API creates explicit Figure and Axes objects and calls methods on them (ax.plot, ax.set_xlabel), which scales far better once you have multiple subplots, need to pass axes into functions, or build reusable plotting code.

# pyplot (state machine) style
plt.plot([1, 2, 3], [4, 5, 6])
plt.xlabel("x")
plt.show()

# Object-oriented style (preferred for anything beyond a one-off script)
fig, ax = plt.subplots()
ax.plot([1, 2, 3], [4, 5, 6])
ax.set_xlabel("x")
plt.show()
Mixing the two styles works for small scripts, but once a figure has multiple subplots, always address a specific Axes (ax.plot(...)) rather than relying on pyplot's "current axes."

🎤 One-Line Interview AnswerA Figure is the whole canvas, an Axes is one plot area with its own x/y data space, and an Axis is a single number line on that Axes; pyplot drives an implicit "current axes," while the object-oriented API addresses Figure/Axes objects directly and scales better for multi-plot code.

Module 2 — Your First Plot

plt.plot · plt.show · Line plots · Chart anatomy

▼

✏️ Drawing your first line

plt.plot(x, y) draws a line connecting paired x and y values; plt.show() renders the figure in a window or, in notebooks, inline. If you pass only one sequence, Matplotlib uses its index positions (0, 1, 2, ...) as the x-values.

import matplotlib.pyplot as plt

x = [1, 2, 3, 4, 5]
y = [2, 4, 6, 8, 10]

plt.plot(x, y)
plt.show()

🔎 The anatomy of a chart

Every chart is built from recognizable parts: the Figure (outer canvas), the Axes (plot area), the data (the line, bars, or points), axis labels, a title, optional tick marks, a legend, and spines (the plot area's border lines). Knowing these names makes documentation and error messages far easier to parse.

fig, ax = plt.subplots()
ax.plot(x, y, label="y = 2x")
ax.set_title("My First Plot")
ax.set_xlabel("x")
ax.set_ylabel("y")
ax.legend()
plt.show()
plt.show() is only needed outside Jupyter notebooks (or when a backend does not auto-display). In a notebook with %matplotlib inline, the figure renders automatically as the last expression of a cell.

🏋️ Practice Questions

  1. Plot y = x**2 for x from 0 to 10 and label both axes.
  2. Name five visual parts of a chart (Figure, Axes, title, tick, spine) and what each one is responsible for.
🎤 One-Line Interview Answerplt.plot(x, y) draws a connected line between paired points and plt.show() renders the figure; a chart's anatomy — Figure, Axes, data, labels, ticks, legend and spines — gives you the vocabulary to customize any part of it.

Module 3 — Figures & Subplots

plt.subplots · Grids of axes · figsize · sharex/sharey

▼

🖼️ Creating a grid with plt.subplots

plt.subplots(nrows, ncols) returns a Figure and either a single Axes or a NumPy array of Axes objects, one per grid cell. This is the standard way to build multi-panel figures, because it hands you addressable Axes objects instead of relying on pyplot's implicit current axes.

import matplotlib.pyplot as plt

fig, axes = plt.subplots(nrows=2, ncols=2, figsize=(10, 6))

axes[0, 0].plot([1, 2, 3], [1, 4, 9])
axes[0, 0].set_title("Top left")
axes[1, 1].bar(["A", "B", "C"], [3, 7, 5])
axes[1, 1].set_title("Bottom right")

fig.tight_layout()
plt.show()

📏 Controlling size and resolution with figsize

figsize=(width, height) sets the figure's size in inches; dpi (dots per inch) controls resolution/sharpness, especially important when saving for print or high-density screens. Larger figsize with the same dpi produces a physically bigger image at the same crispness; higher dpi with the same figsize produces a sharper but larger-in-pixels image.

fig, ax = plt.subplots(figsize=(8, 4), dpi=150)
ax.plot([1, 2, 3], [3, 1, 4])
plt.show()

🔗 Sharing axes with sharex and sharey

sharex=True / sharey=True lock the corresponding axis limits and ticks across subplots, which is essential when comparing panels directly — readers should not have to recheck each panel's scale. plt.subplots(2, 1, sharex=True) is a common layout for stacked time-series panels.

fig, (ax1, ax2) = plt.subplots(2, 1, sharex=True, figsize=(8, 5))
ax1.plot([1, 2, 3, 4], [10, 12, 9, 15])
ax1.set_ylabel("Revenue")
ax2.plot([1, 2, 3, 4], [2, 3, 1, 4])
ax2.set_ylabel("Errors")
ax2.set_xlabel("Day")
plt.show()
Forgetting fig.tight_layout() (or constrained_layout=True in subplots()) on multi-panel figures often leaves titles and labels overlapping or clipped, especially with rotated tick labels.

🏋️ Practice Questions

🎤 One-Line Interview Answerplt.subplots(nrows, ncols) returns a Figure plus an array of addressable Axes for building multi-panel layouts; figsize sets physical size, dpi sets resolution, and sharex/sharey lock axis scales across panels so comparisons are visually fair.

Module 4 — Line Plots in Depth

color · linestyle · linewidth · markers · Multiple series

▼

📈 Styling a line: color, linestyle, linewidth, markers

plot() accepts color (or the shorthand c), linestyle ("-", "--", "-.", ":"), linewidth (or lw), and marker ("o", "s", "^", "x", ...) to control a line's appearance. A compact format string like "ro--" combines color, marker and linestyle in one argument.

import matplotlib.pyplot as plt

x = [1, 2, 3, 4, 5]
y = [2, 3, 5, 7, 11]

fig, ax = plt.subplots()
ax.plot(x, y, color="tab:blue", linestyle="--", linewidth=2, marker="o", markersize=6)
plt.show()

🎻 Plotting multiple series on one Axes

Calling ax.plot() more than once on the same Axes overlays series on shared axes — ideal for comparing trends. Give each call a label and then call ax.legend() once so readers can tell the lines apart; let each series get a distinct color or style rather than relying on memory.

days = [1, 2, 3, 4, 5]
product_a = [20, 25, 22, 30, 28]
product_b = [15, 18, 24, 21, 26]

fig, ax = plt.subplots()
ax.plot(days, product_a, label="Product A", marker="o")
ax.plot(days, product_b, label="Product B", marker="s")
ax.set_xlabel("Day")
ax.set_ylabel("Units sold")
ax.legend()
plt.show()

Module 5 — Bar Charts

Vertical/horizontal · Grouped · Stacked · When to use bars

▼

📊 Vertical and horizontal bars

ax.bar(categories, values) draws vertical bars; ax.barh(categories, values) draws horizontal bars, which read more easily when category labels are long or numerous, since the text runs horizontally instead of being rotated.

import matplotlib.pyplot as plt

languages = ["Python", "JavaScript", "SQL", "Java"]
usage = [68, 55, 49, 33]

fig, ax = plt.subplots()
ax.bar(languages, usage, color="tab:blue")
ax.set_ylabel("Usage (%)")
plt.show()

fig, ax = plt.subplots()
ax.barh(languages, usage, color="tab:orange")
ax.set_xlabel("Usage (%)")
plt.show()

🧱 Grouped and stacked bars

A grouped bar chart places bars for each category's sub-groups side by side, which is best for comparing sub-group magnitudes directly. A stacked bar chart stacks sub-groups on top of each other, which is best for seeing both sub-group values and their total at a glance, at the cost of making it harder to compare middle segments precisely.

import numpy as np

categories = ["Q1", "Q2", "Q3", "Q4"]
product_a = np.array([20, 25, 30, 22])
product_b = np.array([15, 18, 20, 25])
x = np.arange(len(categories))
width = 0.35

fig, ax = plt.subplots()
ax.bar(x - width / 2, product_a, width, label="Product A")
ax.bar(x + width / 2, product_b, width, label="Product B")
ax.set_xticks(x)
ax.set_xticklabels(categories)
ax.legend()
plt.show()

fig, ax = plt.subplots()
ax.bar(categories, product_a, label="Product A")
ax.bar(categories, product_b, bottom=product_a, label="Product B")
ax.legend()
plt.show()

🤔 When a bar chart is the right choice

Bar charts are strongest for comparing discrete categories by magnitude — rankings, counts, survey responses. They are a poor choice for showing a continuous trend over time (a line plot is clearer) or for showing the relationship between two numeric variables (a scatter plot is clearer). Bar charts should also almost always start their value axis at zero, since bar length is the visual cue readers use to judge magnitude.

Use bottom= on ax.bar() to stack a series on top of the previous one; each stacked series' bottom should equal the running sum of everything beneath it.

🏋️ Practice Questions

  1. Draw grouped bars comparing two products across four quarters.
  2. Convert the same data into a stacked bar chart and explain when each version communicates better.
🎤 One-Line Interview Answerax.bar()/ax.barh() draw vertical/horizontal bars; grouped bars (offset by width) compare sub-group magnitudes side by side, while stacked bars (using bottom=) show both parts and totals — and bar charts belong on category comparisons with a zero-based value axis, not on continuous trends.

Module 6 — Scatter Plots

Size encoding · Color encoding · alpha · Overplotting

▼

🎯 A basic scatter and encoding a third variable with size

ax.scatter(x, y) plots individual points rather than connecting them with a line, which is the right choice when you want to examine the relationship between two numeric variables rather than imply a continuous path between observations. Passing an array to s= scales each point's size, letting a third numeric variable (e.g. population, revenue) ride along visually.

import matplotlib.pyplot as plt
import numpy as np

rng = np.random.default_rng(7)
hours_studied = rng.uniform(1, 10, 50)
test_score = hours_studied * 7 + rng.normal(0, 8, 50)
effort = rng.uniform(20, 200, 50)   # third variable -> point size

fig, ax = plt.subplots()
ax.scatter(hours_studied, test_score, s=effort, alpha=0.6)
ax.set_xlabel("Hours studied")
ax.set_ylabel("Test score")
plt.show()

🌈 Encoding a fourth variable with color, and alpha for overplotting

Passing an array to c= colors each point by a numeric or categorical variable, letting one scatter plot encode up to four dimensions (x, y, size, color). alpha (0 to 1) makes points semi-transparent, which is essential when many points overlap ("overplotting") — dense clusters become visibly darker instead of collapsing into an indistinguishable blob.

grade_level = rng.integers(9, 13, 50)   # fourth variable -> color

fig, ax = plt.subplots()
scatter = ax.scatter(hours_studied, test_score, s=effort, c=grade_level,
                      cmap="viridis", alpha=0.7, edgecolors="black", linewidths=0.5)
fig.colorbar(scatter, ax=ax, label="Grade level")
ax.set_xlabel("Hours studied")
ax.set_ylabel("Test score")
plt.show()
With thousands of overlapping points, even alpha stops helping — consider a hexbin plot (ax.hexbin) or a 2D histogram instead, which aggregate density directly rather than relying on visual transparency.

🏋️ Practice Questions

  1. Build a scatter plot where point size encodes a third variable and add appropriate axis labels.
  2. Add alpha=0.3 to a scatter plot of 5,000 overlapping points and describe what changes.
🎤 One-Line Interview Answerax.scatter() encodes up to four variables at once — x position, y position, point size (s=) and point color (c=) — making it the right chart for showing relationships between numeric variables; alpha fights overplotting by letting dense regions visually darken instead of hiding individual points.

Module 7 — Histograms & Distributions

hist · Bin selection · Density vs count · Overlapping histograms

▼

🔔 Drawing a histogram and choosing bins

ax.hist(data, bins=...) buckets continuous values into intervals and plots the count (or density) per bucket, revealing a variable's distribution shape — skew, modality, outliers — that a single summary statistic hides. Too few bins hide structure; too many bins turn the chart into noise. bins="auto" or an explicit integer are reasonable starting points; always sanity-check by trying two or three bin counts.

import matplotlib.pyplot as plt
import numpy as np

rng = np.random.default_rng(1)
scores = rng.normal(loc=72, scale=12, size=500)

fig, ax = plt.subplots()
ax.hist(scores, bins=20, color="tab:blue", edgecolor="white")
ax.set_xlabel("Score")
ax.set_ylabel("Count")
plt.show()

📐 Density vs count

By default hist() plots raw counts per bin. Passing density=True instead normalizes the histogram so the total area under the bars equals 1, turning it into an estimate of a probability density — this is what lets you overlay a fitted distribution curve for comparison, or compare two histograms with different sample sizes on the same vertical scale.

fig, ax = plt.subplots()
ax.hist(scores, bins=20, density=True, color="tab:green", alpha=0.7)
ax.set_ylabel("Density")
plt.show()

🪞 Overlapping histograms for comparison

To compare two groups' distributions, plot both histograms on the same Axes with alpha transparency and consistent bins, and always add a legend so viewers know which color is which group.

group_a = rng.normal(70, 10, 300)
group_b = rng.normal(78, 9, 300)
bins = np.linspace(30, 110, 25)   # shared bin edges for a fair comparison

fig, ax = plt.subplots()
ax.hist(group_a, bins=bins, alpha=0.5, label="Section A")
ax.hist(group_b, bins=bins, alpha=0.5, label="Section B")
ax.legend()
plt.show()
Use the same bins array (not just the same bin count) when comparing two histograms, so bin edges align and the comparison is not distorted by offset buckets.

🏋️ Practice Questions

  1. Plot a histogram of a normal sample with 10, 30 and 100 bins and describe how the shape appears to change.
  2. Overlay two groups' histograms with alpha=0.5 and shared bin edges, and add a legend.
🎤 One-Line Interview Answerax.hist() bins continuous data to reveal distribution shape; bin count is a real analytical choice (too few hides structure, too many adds noise), density=True normalizes area to 1 for comparing differently-sized samples, and overlapping histograms need shared bin edges plus alpha to compare fairly.

Module 8 — Labels, Titles & Legends

Axis labels · Chart titles · Legend placement · Custom handles

▼

🏷️ Axis labels and chart titles

ax.set_xlabel(), ax.set_ylabel() and ax.set_title() (or the pyplot equivalents plt.xlabel, plt.ylabel, plt.title) name what each axis and the chart as a whole represent, including units where relevant (e.g. "Revenue ($M)"). A chart without axis labels forces readers to guess, which undermines even an otherwise well-made plot.

import matplotlib.pyplot as plt

fig, ax = plt.subplots()
ax.plot([1, 2, 3, 4], [10, 14, 11, 18])
ax.set_xlabel("Week")
ax.set_ylabel("Revenue ($K)")
ax.set_title("Weekly Revenue Trend")
plt.show()

🗂️ Controlling legend placement

ax.legend() auto-places a legend using labeled artists (those created with label=). The loc parameter ("upper right", "lower left", "best", ...) controls placement, and bbox_to_anchor moves the legend entirely outside the plotting area when it would otherwise overlap data.

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [1, 2, 3], label="Series A")
ax.plot([1, 2, 3], [3, 2, 1], label="Series B")
ax.legend(loc="upper center", bbox_to_anchor=(0.5, -0.15), ncol=2)
plt.show()

🧩 Building a legend from custom handles

When a chart's colors or markers do not come from simple labeled plot/bar calls (e.g. a scatter colored by a colormap, or a manually composed key), build the legend explicitly from Line2D or Patch handles rather than relying on auto-detection.

from matplotlib.lines import Line2D

handles = [
    Line2D([0], [0], color="tab:blue", marker="o", linestyle="", label="Low risk"),
    Line2D([0], [0], color="tab:red", marker="o", linestyle="", label="High risk"),
]
fig, ax = plt.subplots()
ax.scatter([1, 2, 3], [1, 2, 3], color="tab:blue")
ax.scatter([4, 5], [1, 2], color="tab:red")
ax.legend(handles=handles)
plt.show()

🏋️ Practice Questions

  1. Add an axis-labeled, titled chart and place its legend outside the plot area using bbox_to_anchor.
  2. Build a legend from custom Line2D handles for a scatter plot colored by a third category.
🎤 One-Line Interview AnswerAxis labels and titles via set_xlabel/set_ylabel/set_title tell the reader what they're looking at; ax.legend() auto-builds a key from labeled artists and loc/bbox_to_anchor control its placement, while custom Line2D/Patch handles build a legend when auto-detection does not match what the colors actually mean.

Module 9 — Customizing Ticks & Spines

Locators · Formatters · Rotating labels · Removing spines

▼

📐 Tick locators and formatters

A locator decides where ticks appear (MultipleLocator, MaxNLocator, AutoLocator); a formatter decides how each tick's value is displayed as text (FuncFormatter, PercentFormatter, FixedFormatter). Together they give precise control instead of accepting Matplotlib's automatic defaults.

import matplotlib.pyplot as plt
import matplotlib.ticker as ticker

fig, ax = plt.subplots()
ax.plot([0, 1, 2, 3, 4, 5], [0, 1500, 2800, 2600, 4100, 5000])
ax.xaxis.set_major_locator(ticker.MultipleLocator(1))
ax.yaxis.set_major_formatter(ticker.FuncFormatter(lambda v, pos: f"${v:,.0f}"))
plt.show()

🔄 Rotating tick labels

Long category labels overlap when drawn horizontally. ax.tick_params(axis="x", rotation=45) (or plt.xticks(rotation=45, ha="right")) angles the labels so they stay legible without shrinking the font or truncating text.

categories = ["Customer Support", "Engineering", "Marketing", "Sales", "Finance"]
values = [42, 85, 37, 60, 29]

fig, ax = plt.subplots()
ax.bar(categories, values)
ax.tick_params(axis="x", rotation=45)
fig.tight_layout()
plt.show()

✂️ Removing spines for a cleaner look

Spines are the border lines around the plot area (top, bottom, left, right). Removing the top and right spines is a common, low-risk polish step that reduces visual clutter without losing any information, since those two borders rarely carry meaning.

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [2, 4, 3])
ax.spines["top"].set_visible(False)
ax.spines["right"].set_visible(False)
plt.show()
ax.xaxis.set_major_locator(ticker.MaxNLocator(integer=True)) is a quick fix when an integer-valued axis (like a count) shows confusing fractional tick labels.

🏋️ Practice Questions

  1. Format a y-axis to show values as currency using FuncFormatter.
  2. Rotate x-axis labels 45 degrees for a bar chart with long category names, and remove the top/right spines.
🎤 One-Line Interview AnswerLocators decide where ticks go and formatters decide how their labels read, giving full control over an axis beyond Matplotlib's automatic defaults; rotating long tick labels and hiding the top/right spines are the two most common, lowest-risk polish steps for a cleaner chart.

Module 10 — Annotations & Text

annotate · Arrows · Text positioning · Highlighting a point

▼

💬 Annotating a point with annotate and an arrow

ax.annotate(text, xy=..., xytext=..., arrowprops=...) draws a label connected by an arrow from xytext (where the text sits) to xy (the data point being called out) — the standard way to highlight a specific, meaningful value such as a peak, an outlier or an inflection point.

import matplotlib.pyplot as plt

x = [1, 2, 3, 4, 5, 6]
y = [10, 14, 22, 18, 30, 25]

fig, ax = plt.subplots()
ax.plot(x, y, marker="o")
ax.annotate("Peak value", xy=(5, 30), xytext=(3.2, 33),
            arrowprops=dict(facecolor="black", arrowstyle="->"))
plt.show()

📍 Plain text positioning and highlighting a data point

ax.text(x, y, text) places text at a specific data coordinate without an arrow — useful for labeling individual bars or points directly. Combine it with a distinct marker or color on the highlighted point so the annotation and the data it describes are visually tied together.

fig, ax = plt.subplots()
ax.plot(x, y, marker="o", color="gray")
ax.plot(5, 30, marker="o", color="red", markersize=10)   # highlight the peak
ax.text(5.1, 29, "Record high", color="red", fontsize=10, va="top")
ax.set_ylim(0, 35)
plt.show()
ha (horizontal alignment: "left", "center", "right") and va (vertical alignment: "top", "center", "bottom") control how text is positioned relative to its (x, y) anchor point — essential for keeping labels from colliding with the data or chart edges.

🏋️ Practice Questions

  1. Annotate the minimum point of a line plot with an arrow and a short label.
  2. Highlight one bar in a bar chart with a different color and add its exact value as text above it.
🎤 One-Line Interview Answerax.annotate() draws a text label connected by an arrow to a specific data point, which is the standard way to call out peaks, outliers or thresholds; ax.text() places plain text at a coordinate, and combining a highlighted marker color with nearby text ties the annotation visually to the data it describes.

Module 11 — Colors & Colormaps

Named colors · Sequential · Diverging · Categorical · Misleading choices

▼

🎨 Specifying colors

Matplotlib accepts named colors ("red", "tab:blue"), hex strings ("#1f77b4"), RGB(A) tuples ((0.2, 0.4, 0.6)), or the default "tab10" color cycle used automatically when you don't specify a color. The "tabX" named colors are designed to look good together and are a safe default palette for categorical series.

import matplotlib.pyplot as plt

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [1, 2, 1], color="tab:blue", label="Named")
ax.plot([1, 2, 3], [2, 3, 2], color="#2ca02c", label="Hex")
ax.plot([1, 2, 3], [3, 4, 3], color=(0.8, 0.2, 0.4), label="RGB tuple")
ax.legend()
plt.show()

🌡️ Choosing the right colormap family

Colormaps fall into three families, and picking the wrong one actively distorts how data reads. Sequential colormaps ("viridis", "plasma", "Blues") go from low to high intensity and fit ordered numeric data (e.g. temperature, density). Diverging colormaps ("coolwarm", "RdBu") have a meaningful midpoint and fit data with a natural center, like deviation from zero or from a baseline. Qualitative/categorical colormaps ("tab10", "Set2") use visually distinct, unordered colors and fit discrete categories with no inherent ranking.

Data typeRight colormap familyExample
Ordered numeric magnitudeSequential"viridis", "Blues"
Values with a meaningful zero/midpointDiverging"coolwarm", "RdBu"
Unordered categoriesQualitative"tab10", "Set2"
import numpy as np

data = np.random.default_rng(0).normal(0, 1, (10, 10))
fig, ax = plt.subplots()
im = ax.imshow(data, cmap="coolwarm")   # diverging: data centers around 0
fig.colorbar(im, ax=ax)
plt.show()

⚠️ When a colormap choice misleads

Using a sequential colormap like the old default "jet" on ordered data is a classic mistake: "jet" is not perceptually uniform, so equal numeric steps do not look like equal visual steps, and it can manufacture false boundaries where none exist in the data. Using a diverging colormap on data with no natural midpoint implies a meaningful center that isn't there. Prefer perceptually uniform colormaps ("viridis", "cividis", "magma") for sequential data, and always check your palette against common forms of color vision deficiency.

Applying a rainbow/"jet"-style colormap to continuous scientific data is widely considered a visualization anti-pattern — it can visually exaggerate noise and hide real structure because its perceived brightness does not change uniformly with value.

🏋️ Practice Questions

  1. Plot a heatmap of correlation data (naturally centered at 0) using an appropriate diverging colormap.
  2. Explain why "jet" is a risky default for a sequential variable like elevation or temperature.
🎤 One-Line Interview AnswerColors come from named strings, hex codes, RGB(A) tuples or the default color cycle, but colormap family matters more than color choice alone: use sequential colormaps for ordered magnitude, diverging colormaps only when there's a real midpoint, and categorical colormaps for unordered groups — a mismatched or non-perceptually-uniform colormap like "jet" can visually fabricate structure that isn't in the data.

Module 12 — Multiple Plot Types Together

twinx · Bar + line · Secondary y-axis pitfalls

▼

🔀 Twin axes with twinx

ax.twinx() creates a second Axes sharing the same x-axis but with an independent y-axis, letting you plot two series with very different scales or units (e.g. revenue in dollars and conversion rate in percent) on one chart without one flattening the other.

import matplotlib.pyplot as plt

days = [1, 2, 3, 4, 5]
revenue = [1200, 1500, 1100, 1800, 2000]
conversion_rate = [2.1, 2.4, 1.9, 2.8, 3.0]

fig, ax1 = plt.subplots()
ax1.plot(days, revenue, color="tab:blue", marker="o")
ax1.set_ylabel("Revenue ($)", color="tab:blue")
ax1.tick_params(axis="y", labelcolor="tab:blue")

ax2 = ax1.twinx()
ax2.plot(days, conversion_rate, color="tab:red", marker="s")
ax2.set_ylabel("Conversion rate (%)", color="tab:red")
ax2.tick_params(axis="y", labelcolor="tab:red")

ax1.set_xlabel("Day")
plt.show()

🧮 Combining a bar chart with a line

A common pattern is bars for a volume metric (e.g. monthly orders) with a line overlay for a rate metric (e.g. cumulative percent or a moving average) sharing or twinning the y-axis, giving readers both the raw scale and the trend in one view.

import numpy as np

months = ["Jan", "Feb", "Mar", "Apr", "May"]
orders = [120, 150, 170, 140, 200]
avg_order_value = [45, 47, 44, 50, 52]

fig, ax1 = plt.subplots()
ax1.bar(months, orders, color="lightsteelblue", label="Orders")
ax1.set_ylabel("Orders")

ax2 = ax1.twinx()
ax2.plot(months, avg_order_value, color="darkorange", marker="o", label="Avg order value ($)")
ax2.set_ylabel("Avg order value ($)")

fig.legend(loc="upper left", bbox_to_anchor=(0.12, 0.88))
plt.show()

⚠️ Secondary y-axis pitfalls

A twin/secondary y-axis is easy to misread or, worse, to use manipulatively: two independently-scaled axes can be aligned (even accidentally) to make two unrelated series appear to move together, implying a correlation the data doesn't support. Always color-code each axis and series to match, label both axes explicitly, and consider whether two separate stacked subplots (via sharex=True) communicate more honestly than a single dual-axis chart.

Dual-axis charts are one of the most commonly abused chart types — readers often assume the two axes share a scale or origin unless told otherwise. If a dual-axis chart isn't clearly necessary, a faceted pair of subplots is usually the safer, more honest choice.

Module 13 — Plotting Directly from pandas

.plot() accessor · Underlying matplotlib calls

▼

🐼 The .plot() accessor

Every pandas Series and DataFrame exposes a .plot() accessor that is a thin convenience wrapper over Matplotlib: df.plot(kind="bar"), df.plot.line(), df["col"].plot.hist() all route straight to matplotlib calls, inferring x-values from the index and series names from column names.

import pandas as pd
import matplotlib.pyplot as plt

df = pd.DataFrame({
    "month": ["Jan", "Feb", "Mar", "Apr"],
    "revenue": [1200, 1500, 1100, 1800],
    "costs": [800, 900, 850, 1000],
}).set_index("month")

df.plot(kind="bar", figsize=(7, 4))
plt.ylabel("Amount ($)")
plt.show()

🔧 How .plot() relates to the underlying Matplotlib calls

df.plot() returns an ordinary Matplotlib Axes object, so anything you can do with ax.set_title(), ax.legend() or fig.savefig() still works after calling it — pandas is not a separate plotting engine, it's a convenience layer. Passing ax= lets you draw a pandas plot onto an Axes you created yourself, which is the cleanest way to combine pandas convenience with full Matplotlib control (subplots, twin axes, custom styling).

fig, ax = plt.subplots(figsize=(7, 4))
df["revenue"].plot(kind="line", ax=ax, marker="o", color="tab:green", label="Revenue")
df["costs"].plot(kind="line", ax=ax, marker="s", color="tab:red", label="Costs")
ax.set_title("Revenue vs Costs")
ax.set_ylabel("Amount ($)")
ax.legend()
fig.savefig("revenue_vs_costs.png", dpi=200, bbox_inches="tight")
plt.show()
df.plot(subplots=True) draws one subplot per column automatically — a fast way to eyeball several series at once before building a custom figure.

Module 14 — Saving Figures

savefig · DPI · File formats · bbox_inches="tight"

▼

💾 Saving with savefig and controlling DPI

fig.savefig("name.png") writes the current figure to disk; the format is inferred from the file extension. dpi= controls pixel density at save time — raise it for print or detailed raster output, since plt.show()'s on-screen rendering may not reflect the saved file's final resolution.

import matplotlib.pyplot as plt

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [1, 4, 9])
fig.savefig("chart.png", dpi=300)

🖨️ Choosing a format for print vs web

Raster formats (PNG, JPEG) store a fixed pixel grid: PNG is lossless and best for charts with sharp lines/text; JPEG suits photographic content but introduces compression artifacts around sharp chart edges, so it's rarely a good fit for plots. Vector formats (PDF, SVG, EPS) store drawing instructions rather than pixels, so they stay perfectly sharp at any zoom or print size — the standard choice for journal figures, posters, or anything that will be resized or printed.

Use caseRecommended formatWhy
Web/dashboard displayPNGLossless, universally supported, reasonable file size
Print or publication figurePDF or SVGInfinitely scalable, no pixelation
Editable in design softwareSVG or EPSVector paths remain editable
Embedding in a Word/PowerPoint docPNG (high dpi) or EMFBroad compatibility
fig.savefig("chart.pdf")          # vector, perfect for print/publication
fig.savefig("chart.svg")          # vector, editable, web-friendly
fig.savefig("chart_web.png", dpi=150)   # raster, good for web/dashboards

✂️ bbox_inches="tight" and transparent backgrounds

By default, savefig can clip axis labels, titles, or legends placed outside the plot area. bbox_inches="tight" recalculates the saved bounding box to include everything, trimming excess whitespace in the process. transparent=True saves without a background fill, useful for overlaying a chart onto a colored slide or webpage.

fig.savefig("chart_clean.png", dpi=300, bbox_inches="tight", transparent=True)
Always call savefig() *before* plt.show() in scripts — in some backends, show() can clear or close the figure, producing a blank or missing saved file afterward.

🎭 Switching the whole look with plt.style.use

plt.style.use("style-name") applies a bundle of defaults (colors, fonts, grid, backgrounds) to every subsequent plot in the session, giving a consistent look without manually restyling each chart. Built-in styles include "ggplot", "seaborn-v0_8", "fivethirtyeight", "dark_background", and "bmh"; plt.style.available lists everything installed.

import matplotlib.pyplot as plt

fig, ax = plt.subplots()
ax.plot([1, 2, 3, 4], [1, 4, 9, 16])

⚙️ rcParams for fine-grained global defaults

plt.rcParams is a dictionary-like object controlling every default Matplotlib setting — font size, line width, figure size, grid visibility, and more. Editing it directly gives finer control than a packaged style, and it's the standard way to set one global default (like a larger base font size for presentation slides) without affecting anything else.

plt.rcParams["figure.figsize"] = (8, 5)
plt.rcParams["font.size"] = 12
plt.rcParams["axes.grid"] = True
plt.rcParams["lines.linewidth"] = 2

fig, ax = plt.subplots()

plt.show()
Use with plt.style.context("ggplot"): to apply a style only within a with block, leaving global settings untouched for code that runs afterward — safer than plt.style.use() inside shared notebooks or libraries.

Module 16 — Common Mistakes & Best Practices

Truncated y-axis · Chart junk · Right chart for the data · Colorblind-safe palettes

▼

⚠️ Misleading axes and a truncated y-axis

Starting a bar chart's y-axis above zero visually exaggerates differences between bars, since bar length (not just position) is the cue readers use for magnitude — a 2% real difference can look like a 10x difference if the axis starts at, say, 90 instead of 0. Line charts are more forgiving of a non-zero baseline since position (not length) carries the signal, but any truncation should be labeled clearly so it isn't missed.

import matplotlib.pyplot as plt

values = [95, 97, 94, 98]

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 4))
ax1.bar(["A", "B", "C", "D"], values)
ax1.set_ylim(0, 100)
ax1.set_title("Honest: starts at 0")

ax2.bar(["A", "B", "C", "D"], values)
ax2.set_ylim(90, 100)
ax2.set_title("Misleading: truncated axis")
plt.show()

🧹 Chart junk and the right chart for the data

"Chart junk" is any visual element that doesn't convey data — heavy gridlines, 3D effects on 2D data, decorative gradients, redundant legends — and it competes with the actual information for attention. Pair that discipline with choosing the right chart family in the first place: lines for trends over a continuous axis, bars for category comparisons, scatter for relationships between two numeric variables, histograms for single-variable distributions. The wrong chart type can't be fixed by better styling.

GoalRight chartAvoid
Trend over timeLine plotPie chart, 3D bar
Compare categoriesBar chartLine plot (implies continuity)
Relationship between two numeric variablesScatter plotBar chart
Distribution of one variableHistogram / box plotSingle bar of the mean only
Part-to-whole (few categories)Stacked barExploded 3D pie

✅ Accessibility and colorblind-safe palettes

Roughly 1 in 12 men have some form of color vision deficiency, most commonly red-green. Relying on red-vs-green alone to distinguish series (a frequent default for "good/bad" charts) excludes a meaningful share of readers. Use colorblind-safe, perceptually uniform palettes ("viridis", "cividis", or Okabe-Ito categorical colors), and back up color coding with a second channel — different markers, linestyles, or direct labels — so the chart still works in grayscale or for colorblind viewers.

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [1, 2, 1], color="tab:blue", marker="o", label="Group A")
ax.plot([1, 2, 3], [2, 3, 2], color="tab:orange", marker="s", linestyle="--", label="Group B")
ax.legend()
plt.show()
Red/green as the *only* distinguishing cue between two series is one of the most common and most avoidable accessibility failures in data visualization; always add a second visual channel (shape, pattern, or direct labeling).

Module 17 — Matplotlib Interview Questions

Core concepts · API choices · Practical scenarios

▼

Q: What's the difference between a Figure and an Axes?

A Figure is the entire canvas or window that can hold one or more plots; an Axes is a single plot area within that figure, with its own x/y data range, title and ticks. In code, fig, ax = plt.subplots() gives you one Figure and one Axes, while fig, axes = plt.subplots(2, 2) gives you one Figure holding a 2x2 array of four Axes. The distinction matters because almost every customization method — set_title, set_xlabel, legend — is called on the Axes, not the Figure; the Figure mainly handles things like overall size, saving, and arranging subplots.

Q: Should I use the pyplot API or the object-oriented API, and why?

For a quick, throwaway single-plot script, plt.plot()/plt.show() is fine and faster to type. For anything with multiple subplots, reusable plotting functions, or code that will be maintained, I use the object-oriented API — explicit fig, ax = plt.subplots() then ax.plot(), ax.set_title(), and so on. The OO API avoids pyplot's implicit "current axes" state, which becomes ambiguous and error-prone once a script has more than one Axes or when plotting happens inside functions. Most production codebases standardize on the OO API for exactly that reason.

Q: How do you create a grid of subplots, and how do you address an individual one?

fig, axes = plt.subplots(nrows, ncols) returns a NumPy array of Axes objects shaped (nrows, ncols); you index into it like axes[0, 1] to get a specific panel and call plotting methods on that Axes directly. If nrows or ncols is 1, axes collapses to a 1D array or a single Axes object, so I either guard for that or pass squeeze=False to always get a consistent 2D array. I follow up with fig.tight_layout() or constrained_layout=True to prevent titles and labels from overlapping between panels.

Q: How do you control figure size and resolution for a publication-quality chart?

figsize=(width, height) in inches controls the physical size, and dpi controls how many pixels are packed into each inch — together they determine the final pixel dimensions of a rendered or saved figure. For print or journal submission I typically set a modest figsize matching the target column width and a high dpi (300 or more) on savefig, plus a vector format like PDF or SVG so the figure stays crisp at any size rather than depending on a fixed pixel count at all.

Q: What's the correct way to save a figure so nothing gets cut off?

I call fig.savefig("name.png", dpi=300, bbox_inches="tight") before calling plt.show(). bbox_inches="tight" recalculates the saved bounding box to include elements that sit outside the main axes, like a legend placed via bbox_to_anchor or rotated tick labels, which would otherwise get clipped. Order matters: in some backends calling show() first can clear the figure, so I always save first, display second, in any script meant to produce a file.

Q: How do you decide between a line chart, bar chart, scatter plot, and histogram?

I match the chart to the question. A line chart suits a trend over a continuous, ordered axis like time. A bar chart suits comparing magnitudes across discrete categories, and should almost always start its value axis at zero. A scatter plot suits examining the relationship between two numeric variables. A histogram suits the distribution of a single numeric variable. Picking the wrong family — like a line chart over unordered categories, which implies a continuity that doesn't exist — misleads readers no matter how well the chart is styled afterward.

Q: How do you customize ticks, and when would you need to?

I use locators to control where ticks appear (MultipleLocator, MaxNLocator) and formatters to control how their labels are displayed (FuncFormatter, PercentFormatter). I reach for this when the automatic defaults produce confusing output — fractional ticks on an integer-only axis, dates that need a custom format, or values that should show as currency or percentages. For long categorical labels I rotate tick text with ax.tick_params(axis="x", rotation=45) rather than shrinking the font, which keeps the labels legible.

Q: How do legends work, and how do you place one outside the plot?

ax.legend() automatically collects every artist created with a label= argument and builds a key; loc controls placement within the axes, like "upper right". To move a legend fully outside the plotting area — common when it would otherwise cover data — I use bbox_to_anchor together with loc, for example ax.legend(loc="upper center", bbox_to_anchor=(0.5, -0.15), ncol=2) to place a horizontal legend below the chart. When the colors or markers in a chart don't come from simple labeled calls, I build the legend manually from Line2D or Patch handles instead of relying on auto-detection.

Q: What is twinx used for, and what's the risk of using it?

ax.twinx() creates a second y-axis sharing the same x-axis, which lets you plot two series with very different units or scales — like revenue in dollars and a conversion rate in percent — on one chart. The risk is that dual-axis charts are easy to misread or even construct to mislead, because two independently scaled axes can be aligned so unrelated series appear correlated when they aren't. I color-code each axis to match its series and consider whether two stacked subplots with sharex=True would tell the story more honestly before defaulting to a dual axis.

Q: How does plotting from pandas relate to plotting with Matplotlib directly?

DataFrame.plot() and Series.plot() are convenience accessors that call Matplotlib under the hood and return an ordinary Axes object — pandas isn't a separate rendering engine, just a shortcut that infers x-values from the index and series names from columns. Because the return value is a real Axes, I can keep customizing it afterward with ax.set_title() or ax.legend(), or pass in my own ax= to combine a pandas-drawn series with other Matplotlib elements on the same figure.

Q: How do you handle a scatter plot with tens of thousands of overlapping points?

A first step is lowering alpha so dense regions visually darken instead of collapsing into a solid blob, and shrinking marker size with s=. Beyond a certain density, transparency alone stops helping — at that point I switch to an aggregated view like ax.hexbin() or a 2D histogram (ax.hist2d), which bin and color by point density directly rather than relying on the eye to parse thousands of overlapping markers. Downsampling or plotting a representative random subsample is also reasonable when the full dataset isn't necessary to see the pattern.

Q: How do you choose a colormap, and what can go wrong?

I match the colormap family to the data: sequential colormaps like "viridis" for ordered magnitude with no natural center, diverging colormaps like "coolwarm" only when there's a meaningful midpoint such as deviation from zero, and qualitative colormaps like "tab10" for unordered categories. The classic mistake is using a non-perceptually-uniform colormap like the old "jet" default on continuous data — its perceived brightness doesn't change uniformly with value, so it can visually manufacture boundaries or hide real structure that isn't actually in the data.

Q: What's the difference between a view/copy-style trap in data prep and a visualization-level mistake like a truncated axis?

They're different failure modes but both distort what the reader concludes. A truncated y-axis on a bar chart exaggerates the apparent difference between bars because bar *length* carries the visual signal, and starting above zero inflates small real differences into large-looking ones — that's a chart-construction mistake. Upstream of that, if the underlying data itself was wrongly aggregated or filtered (a data-prep mistake), no amount of correct axis scaling fixes a wrong number; I always sanity-check the data going into a chart independently of how the chart itself is styled.

Q: How would you make a chart accessible to colorblind viewers?

I avoid relying on color alone, and specifically avoid red-vs-green as the only way to distinguish two series, since that's the most common form of color vision deficiency. I back color coding with a second channel — different markers, linestyles, or direct data labels — and prefer perceptually uniform, colorblind-safe palettes like "viridis" or "cividis" over the rainbow-style maps that read very differently (or not at all) to colorblind viewers. Checking a chart in grayscale is a quick sanity test: if the series become indistinguishable, color was doing too much of the work.

🎤 One-Line Interview AnswerStrong Matplotlib interview answers connect API choices to the underlying Figure/Axes model and to real chart-design trade-offs — when to use the object-oriented API, how to pick the right chart and colormap for the data, and how axis scaling, dual axes, and overplotting can each quietly mislead if left unchecked.
