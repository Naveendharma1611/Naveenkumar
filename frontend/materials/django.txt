@module m1 | 🧭 | 1 · Intro | Module 1 — Introduction to Django | What is Django · MVT architecture · Request–response cycle · Django vs Flask vs FastAPI
@topic 🌿 What is Django?
Django is a high-level **Python web framework** for building secure, maintainable websites quickly. It follows the **"batteries included"** idea: authentication, an admin panel, an ORM, forms, security protections and much more come built in.
@table
Aspect | Detail
Created | 2003–2005 at the Lawrence Journal-World newspaper (Adrian Holovaty, Simon Willison)
Maintained by | The Django Software Foundation (open source, BSD licence)
Language | Python
Used by | Instagram, Pinterest, Mozilla, Disqus, Eventbrite, NASA
Motto | "The web framework for perfectionists with deadlines"
@end
@topic ⚡ Key Features
- **ORM** — work with the database using Python classes instead of SQL
- **Admin panel** — a complete content-management UI generated from your models
- **Authentication** — users, passwords, sessions, permissions and groups
- **Forms** — validation and HTML rendering
- **Security** — protection against SQL injection, XSS, CSRF and clickjacking by default
- **Scalable ecosystem** — Django REST Framework, Celery, Channels and thousands of packages
@topic 🏛️ MVT Architecture
@table
Part | Role | File
Model | Data and business rules; talks to the database through the ORM | `models.py`
View | Receives a request, runs the logic, returns a response | `views.py`
Template | The HTML presentation with placeholders | `templates/*.html`
URL dispatcher | Maps each URL to a view | `urls.py`
@end
@info MVT is Django's version of MVC: Django's **view** plays the role of the MVC controller, and the **template** is the MVC view.
@topic 🔄 The Request–Response Cycle
1. The browser requests a URL, for example `/post/hello-django/`.
2. Middleware processes the request (sessions, security, authentication).
3. `urls.py` matches the URL and calls the right view.
4. The view uses models (the ORM) to read or save data.
5. The view renders a template with that data.
6. An `HttpResponse` travels back through the middleware to the browser.
@topic ⚖️ Django vs Flask vs FastAPI
@table
Feature | Django | Flask | FastAPI
Style | Full-stack, batteries included | Micro-framework, add what you need | API-first, async
Admin, ORM, auth built in | Yes | No (extensions) | No
Best for | Content sites, dashboards, SaaS, large apps | Small apps, custom stacks | High-performance JSON APIs
Learning curve | Medium | Easy | Easy–medium
@end

@interview Django is a batteries-included Python web framework using the MVT pattern: URLs route requests to views, views use models through the ORM and render templates, and middleware wraps every request and response.

@module m3 | 🔗 | 3 · URLs & Views | Module 3 — URLs & Views | Function views · HttpResponse · path() · include() · Converters · Named URLs · reverse()
@topic 👁️ Your First Views
A view is a Python function that takes a `request` and returns a `response`.
@code python
# blog/views.py
from django.http import HttpResponse, JsonResponse


def home(request):
    return HttpResponse("<h1>Welcome to my blog</h1>")


def post_detail(request, post_id):
    return HttpResponse(f"You are reading post {post_id}")


def api_status(request):
    return JsonResponse({"status": "ok", "posts": 3})
@end
@topic 🗺️ Mapping URLs to Views
@code python
# blog/urls.py
from django.urls import path

from . import views

app_name = "blog"          # namespace: use "blog:home" when reversing

urlpatterns = [
    path("", views.home, name="home"),
    path("posts/<int:post_id>/", views.post_detail, name="post_detail"),
    path("api/status/", views.api_status, name="api_status"),
]
@end
@code python
# mysite/urls.py
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("blog.urls")),   # hand everything else to the blog app
]
@end
Visiting `/posts/7/` calls `post_detail(request, post_id=7)`.
@topic 🔢 Path Converters
@table
Converter | Matches | Example URL
`<int:id>` | Positive integers | `/posts/7/`
`<str:name>` | Any text without `/` (the default) | `/users/asha/`
`<slug:slug>` | Letters, numbers, hyphens, underscores | `/post/hello-django/`
`<uuid:uid>` | A UUID | `/orders/075194d3-…/`
`<path:file>` | Any text including `/` | `/files/docs/a.pdf`
@end
@topic 🏷️ Named URLs and reverse()
Never hard-code URLs. Give each route a **name** and build URLs from it, so changing a path later updates every link.
@code python
from django.urls import reverse

reverse("blog:post_detail", args=[5])      # "/posts/5/"
reverse("blog:home")                       # "/"
@end
@code html
<!-- In a template -->
<a href="{% url 'blog:post_detail' 5 %}">Read post 5</a>
@end
@topic 📨 The Request Object and Shortcuts
@table
Attribute | Contains
`request.method` | `"GET"`, `"POST"` …
`request.GET` / `request.POST` | Query-string / form data (dictionary-like)
`request.FILES` | Uploaded files
`request.user` | The logged-in user (or `AnonymousUser`)
`request.path`, `request.headers` | The URL path and HTTP headers
@end
@code python
from django.http import Http404
from django.shortcuts import redirect


def old_url(request):
    return redirect("blog:home")          # 302 redirect to a named URL


def secret(request):
    raise Http404("Nothing here")         # shows the 404 page
@end

@topic 🧩 Template Language
@table
Syntax | Meaning | Example
`{{ variable }}` | Output a value (HTML-escaped automatically) | `{{ post.title }}`
`{% tag %}` | Logic: loops, conditions, URLs | `{% for post in posts %}`
`{{ value\|filter }}` | Transform a value | `{{ post.title\|upper }}`
`{# comment #}` | Template comment | `{# not shown #}`
@end
@code html
{% if posts %}
  <ul>
  {% for post in posts %}
    <li>{{ forloop.counter }}. {{ post.title }} ({{ post.views }} views)</li>
  {% empty %}
    <li>No posts yet.</li>
  {% endfor %}
  </ul>
{% endif %}
@end
@topic 🧪 Useful Filters
@table
Filter | Example | Result
`upper`, `lower`, `title` | `{{ "django"\|title }}` | Django
`date` | `{{ post.created\|date:"d M Y" }}` | 25 Sep 2026
`truncatewords` | `{{ body\|truncatewords:20 }}` | First 20 words…
`default` | `{{ bio\|default:"No bio" }}` | Fallback text
`length`, `pluralize` | `{{ n }} post{{ n\|pluralize }}` | 1 post / 3 posts
`linebreaks` | `{{ body\|linebreaks }}` | Paragraphs from line breaks
`safe` | `{{ html\|safe }}` | Turns off escaping (only for trusted HTML!)
@end
@topic 🏗️ Template Inheritance
A **base** template defines the page skeleton with `{% block %}` placeholders; child templates **extend** it and fill the blocks.
@code html
<!-- templates/base.html -->
{% load static %}
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>{% block title %}My Blog{% endblock %}</title>
  <link rel="stylesheet" href="{% static 'css/style.css' %}">
</head>
<body>
  <nav><a href="{% url 'blog:home' %}">Home</a></nav>
  <main>{% block content %}{% endblock %}</main>
</body>
</html>
@end
@code html
<!-- templates/blog/post_list.html -->
{% extends "base.html" %}
{% block title %}Blog{% endblock %}
{% block content %}
  <h1>Latest posts</h1>
  {% for post in posts %}
    <h2>{{ post.title }}</h2>
  {% endfor %}
{% endblock %}
@end
@tip Reuse fragments with `{% include "partials/post_card.html" %}`, and load CSS, JavaScript and images with `{% load static %}` and `{% static 'path' %}`.

@interview render() combines a template with a context; templates use {{ }} for escaped variables, {% %} for tags such as for/if/url, filters to transform values, and inheritance via extends and block to share layouts.

@module m5 | 🗃️ | 5 · Models | Module 5 — Models & Migrations | Model classes · Field types · Field options · Meta · __str__ · makemigrations · migrate
@topic 🗃️ Defining a Model
A model is a Python class that describes a database table. Each attribute is a column.
@code python
# blog/models.py
from django.db import models
from django.urls import reverse


class Post(models.Model):
    class Status(models.TextChoices):
        DRAFT = "DR", "Draft"
        PUBLISHED = "PB", "Published"

    title = models.CharField(max_length=200)
    slug = models.SlugField(max_length=200, unique=True)
    body = models.TextField()
    status = models.CharField(max_length=2, choices=Status.choices, default=Status.DRAFT)
    views = models.PositiveIntegerField(default=0)
    created = models.DateTimeField(auto_now_add=True)   # set once, on creation
    updated = models.DateTimeField(auto_now=True)       # set on every save

    class Meta:
        ordering = ["-created"]                         # newest first by default

    def __str__(self):
        return self.title

    def get_absolute_url(self):
        return reverse("blog:post_detail", args=[self.slug])
@end
@topic 🔤 Common Field Types
@table
Field | Stores | Notes
`CharField(max_length=…)` | Short text | `max_length` is required
`TextField` | Long text | No length limit
`IntegerField`, `PositiveIntegerField` | Whole numbers |
`DecimalField(max_digits, decimal_places)` | Exact decimals | Use for money
`BooleanField` | True / False |
`DateField`, `DateTimeField` | Dates and times | `auto_now_add`, `auto_now`
`EmailField`, `URLField`, `SlugField` | Validated text |
`ImageField`, `FileField` | Uploaded files | ImageField needs Pillow
`JSONField`, `UUIDField` | JSON data, UUIDs |
`ForeignKey`, `ManyToManyField`, `OneToOneField` | Relationships | Module 8
@end
@topic ⚙️ Field Options
@table
Option | Meaning
`null=True` | The **database** column may be NULL
`blank=True` | **Forms and validation** allow the field to be empty
`default=…` | Value used when none is given
`unique=True` | No two rows may share the value
`choices=…` | Limit to a list of options (shown as a dropdown)
`db_index=True` | Add a database index
`verbose_name`, `help_text` | Labels and help shown in forms and the admin
@end
@info For text fields use `blank=True` alone — Django stores an empty string instead of NULL. Use `null=True, blank=True` for optional numbers, dates and foreign keys.
@topic 🔁 Migrations
Migrations are Python files that record every change to your models, so the database schema can be created and updated step by step on any machine.
@code bash
python manage.py makemigrations          # create migration files from model changes
python manage.py migrate                 # apply them to the database
python manage.py showmigrations          # list applied / pending migrations
python manage.py sqlmigrate blog 0001    # show the SQL a migration will run
@end
@warn Commit migration files to Git, and never edit the database tables by hand — always change the model and make a new migration.

@interview Models are Python classes mapped to tables, with field types and options such as null, blank, default, unique and choices; makemigrations records model changes as migration files and migrate applies them to the database.

@module m7 | 🔍 | 7 · ORM Queries | Module 7 — Querying with the ORM | Create · Read · Update · Delete · Field lookups · Lazy QuerySets · get_object_or_404
@topic 🐚 Try Queries in the Shell
@code bash
python manage.py shell
@end
@code python
from blog.models import Post

# CREATE
post = Post.objects.create(title="Hello Django", slug="hello-django", body="My first post")
# or: post = Post(title=…); post.save()

# READ
Post.objects.all()                          # every post (a QuerySet)
Post.objects.get(slug="hello-django")       # exactly one object
Post.objects.filter(status="PB")            # matching posts
Post.objects.exclude(status="PB")           # non-matching posts
Post.objects.order_by("-views")[:5]         # top 5 by views (LIMIT 5)
Post.objects.filter(title__icontains="django").count()
Post.objects.filter(views__gt=100).exists()
Post.objects.values_list("title", flat=True)   # just the titles
Post.objects.first(), Post.objects.last()

# UPDATE
post.title = "Hello, Django!"
post.save()
Post.objects.filter(status="DR").update(status="PB")   # many rows at once

# DELETE
post.delete()
@end
@warn `get()` raises `Post.DoesNotExist` when nothing matches and `MultipleObjectsReturned` when more than one row matches. Use `filter().first()` when "none" is a normal case.
@topic 🔎 Field Lookups
Lookups are written as `field__lookup=value`.
@table
Lookup | SQL equivalent | Example
`exact` / `iexact` | `=` / case-insensitive `=` | `title__iexact="hello"`
`contains` / `icontains` | `LIKE '%x%'` | `body__icontains="orm"`
`startswith` / `endswith` | `LIKE 'x%'` / `LIKE '%x'` | `slug__startswith="how-to"`
`gt`, `gte`, `lt`, `lte` | `>`, `>=`, `<`, `<=` | `views__gte=100`
`in` | `IN (…)` | `id__in=[1, 2, 3]`
`range` | `BETWEEN` | `views__range=(10, 100)`
`isnull` | `IS NULL` | `category__isnull=True`
`year`, `month`, `date` | Date parts | `created__year=2026`
@end
@topic 💤 QuerySets are Lazy
Building a QuerySet doesn't touch the database. The query runs only when you **use** the results — loop over them, slice with a step, call `list()`, `len()`, `count()` or print them. That's why you can chain filters freely:
@code python
qs = Post.objects.filter(status="PB")        # no query yet
qs = qs.filter(views__gt=50).order_by("-created")
print(qs.query)                               # see the SQL
for post in qs:                               # the query runs here, once
    print(post.title)
@end
@topic 🧯 get_object_or_404 in Views
@code python
# In blog/views.py
from django.shortcuts import get_object_or_404, render

from .models import Post


def post_detail(request, slug):
    post = get_object_or_404(Post, slug=slug, status=Post.Status.PUBLISHED)
    return render(request, "blog/post_detail.html", {"post": post})
@end

@module m8 | 🔗 | 8 · Relationships | Module 8 — Relationships | ForeignKey · ManyToMany · OneToOne · on_delete · related_name · Querying across tables
@topic 🔗 The Complete Blog Models
Now the blog gets authors, categories, tags and comments.
@code python
# blog/models.py
from django.conf import settings
from django.db import models
from django.urls import reverse


class PostQuerySet(models.QuerySet):
    def published(self):
        return self.filter(status=Post.Status.PUBLISHED)


class Category(models.Model):
    name = models.CharField(max_length=100, unique=True)
    slug = models.SlugField(max_length=100, unique=True)

    class Meta:
        verbose_name_plural = "categories"
        ordering = ["name"]

    def __str__(self):
        return self.name


class Tag(models.Model):
    name = models.CharField(max_length=50, unique=True)

    def __str__(self):
        return self.name


class Post(models.Model):
    class Status(models.TextChoices):
        DRAFT = "DR", "Draft"
        PUBLISHED = "PB", "Published"

    title = models.CharField(max_length=200)
    slug = models.SlugField(max_length=200, unique=True)
    author = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE, related_name="posts")
    category = models.ForeignKey(Category, on_delete=models.SET_NULL, null=True, blank=True, related_name="posts")
    tags = models.ManyToManyField(Tag, blank=True, related_name="posts")
    body = models.TextField()
    image = models.ImageField(upload_to="posts/", blank=True)
    status = models.CharField(max_length=2, choices=Status.choices, default=Status.DRAFT)
    views = models.PositiveIntegerField(default=0)
    created = models.DateTimeField(auto_now_add=True)
    updated = models.DateTimeField(auto_now=True)

    objects = PostQuerySet.as_manager()      # adds Post.objects.published() (Module 9)

    class Meta:
        ordering = ["-created"]
        indexes = [models.Index(fields=["status", "-created"])]

    def __str__(self):
        return self.title

    def get_absolute_url(self):
        return reverse("blog:post_detail", args=[self.slug])


class Comment(models.Model):
    post = models.ForeignKey(Post, on_delete=models.CASCADE, related_name="comments")
    name = models.CharField(max_length=80)
    body = models.TextField()
    created = models.DateTimeField(auto_now_add=True)
    active = models.BooleanField(default=True)

    class Meta:
        ordering = ["created"]

    def __str__(self):
        return f"Comment by {self.name} on {self.post}"
@end
@table
Relationship | Field | Example
Many-to-one | `ForeignKey` | Many posts → one author, one category
Many-to-many | `ManyToManyField` | Posts ↔ tags (Django creates the junction table)
One-to-one | `OneToOneField` | User ↔ profile
@end
@topic 🗑️ on_delete Options
@table
Option | When the referenced object is deleted…
`CASCADE` | Delete this object too (delete a user → delete their posts)
`PROTECT` | Refuse the delete (raises ProtectedError)
`RESTRICT` | Refuse, unless it's being deleted through a CASCADE
`SET_NULL` | Set the field to NULL (needs `null=True`)
`SET_DEFAULT` | Set the field to its default
`DO_NOTHING` | Do nothing (the database decides — rarely what you want)
@end
@topic 🧭 Querying Across Relationships
Double underscores follow relationships; `related_name` names the reverse direction.
@code python
from blog.models import Category, Post, Tag

Post.objects.filter(author__username="asha")          # forward: post → author
Post.objects.filter(category__name="Django")
Post.objects.filter(tags__name__in=["python", "orm"]).distinct()

asha.posts.all()                                      # reverse: author → posts (related_name)
django_category.posts.count()
post.comments.filter(active=True)

post.tags.add(python_tag, orm_tag)                    # many-to-many helpers
post.tags.remove(orm_tag)
post.tags.set([python_tag])
post.tags.clear()
@end
@info Without `related_name`, the reverse accessor is `<model>_set`, for example `user.post_set.all()`.

@topic 🚀 The N+1 Problem: select_related and prefetch_related
@code python
# ❌ 1 query for posts + 1 query PER post for its author = N+1 queries
for post in Post.objects.all():
    print(post.author.username)

# ✅ select_related: follows ForeignKey / OneToOne with a SQL JOIN → 1 query
for post in Post.objects.select_related("author", "category"):
    print(post.author.username, post.category)

# ✅ prefetch_related: many-to-many and reverse relations → 1 extra query in total
for post in Post.objects.prefetch_related("tags", "comments"):
    print([tag.name for tag in post.tags.all()])
@end
@table
Method | Use for | How
`select_related` | ForeignKey, OneToOne (forward) | SQL JOIN in the same query
`prefetch_related` | ManyToMany, reverse ForeignKey | A second query, joined in Python
@end

@topic 📝 Defining a Form
@code python
# In blog/forms.py (the full file is in Module 11)
from django import forms


class ContactForm(forms.Form):
    name = forms.CharField(max_length=100)
    email = forms.EmailField()
    subject = forms.CharField(max_length=150)
    message = forms.CharField(widget=forms.Textarea)

    def clean_name(self):                       # validate one field
        name = self.cleaned_data["name"].strip()
        if len(name) < 2:
            raise forms.ValidationError("Please enter your full name.")
        return name

    def clean(self):                            # validate fields together
        cleaned = super().clean()
        if "http" in cleaned.get("subject", "") and "http" in cleaned.get("message", ""):
            raise forms.ValidationError("Links in both subject and message look like spam.")
        return cleaned
@end
@topic 🔁 The Standard View Pattern

# In blog/views.py (the full file is in Module 12)
from django.contrib import messages
from django.shortcuts import redirect, render

from .forms import ContactForm


def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)          # bound form with the submitted data
        if form.is_valid():                       # runs every validation
            name = form.cleaned_data["name"]      # clean, converted values
            messages.success(request, f"Thanks {name}, we'll reply soon!")
            return redirect("blog:contact")       # Post/Redirect/Get: avoids resubmitting
    else:
        form = ContactForm()                      # empty form
    return render(request, "blog/contact.html", {"form": form})

@login_required

@topic 🏛️ Generic Class-Based Views
Class-based views (CBVs) package common patterns — list, detail, create, update, delete — so you only write what's different.
@table
View | Does | Default template
`ListView` | List of objects (+ pagination) | `blog/post_list.html`
`DetailView` | One object by pk or slug | `blog/post_detail.html`
`CreateView` | Form to create an object | `blog/post_form.html`
`UpdateView` | Form to edit an object | `blog/post_form.html`
`DeleteView` | Confirm and delete | `blog/post_confirm_delete.html`
`TemplateView` | Just render a template | you choose

@topic 🧱 The Blog's Views
@code python
# blog/views.py
from django.contrib import messages
from django.contrib.auth.mixins import LoginRequiredMixin, UserPassesTestMixin
from django.db.models import F, Q
from django.shortcuts import get_object_or_404, redirect, render
from django.urls import reverse_lazy
from django.views.decorators.http import require_POST
from django.views.generic import CreateView, DeleteView, DetailView, ListView, UpdateView

from .forms import CommentForm, ContactForm, PostForm
from .models import Post


class PostListView(ListView):
    template_name = "blog/post_list.html"
    context_object_name = "posts"
    paginate_by = 5

    def get_queryset(self):
        qs = Post.objects.published().select_related("author", "category")
        query = self.request.GET.get("q")
        if query:
            qs = qs.filter(Q(title__icontains=query) | Q(body__icontains=query))
        return qs


class PostDetailView(DetailView):
    template_name = "blog/post_detail.html"
    context_object_name = "post"

    def get_queryset(self):
        return Post.objects.published().select_related("author").prefetch_related("tags", "comments")

    def get_object(self, queryset=None):
        post = super().get_object(queryset)
        Post.objects.filter(pk=post.pk).update(views=F("views") + 1)
        return post

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["comment_form"] = CommentForm()
        return context


class AuthorRequiredMixin(UserPassesTestMixin):
    """Only the post's author may edit or delete it."""

    def test_func(self):
        return self.get_object().author == self.request.user


class PostCreateView(LoginRequiredMixin, CreateView):
    model = Post
    form_class = PostForm
    template_name = "blog/post_form.html"
    success_url = reverse_lazy("blog:post_list")

    def form_valid(self, form):
        form.instance.author = self.request.user
        messages.success(self.request, "Post created.")
        return super().form_valid(form)


class PostUpdateView(LoginRequiredMixin, AuthorRequiredMixin, UpdateView):
    model = Post
    form_class = PostForm
    template_name = "blog/post_form.html"
    success_url = reverse_lazy("blog:post_list")


class PostDeleteView(LoginRequiredMixin, AuthorRequiredMixin, DeleteView):
    model = Post
    template_name = "blog/post_confirm_delete.html"
    success_url = reverse_lazy("blog:post_list")


@require_POST
def add_comment(request, slug):
    post = get_object_or_404(Post.objects.published(), slug=slug)
    form = CommentForm(request.POST)
    if form.is_valid():
        comment = form.save(commit=False)
        comment.post = post
        comment.save()
        messages.success(request, "Comment added.")
    return redirect(post)


def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
        if form.is_valid():
            messages.success(request, f"Thanks {form.cleaned_data['name']}, we'll reply soon!")
            return redirect("blog:contact")
    else:
        form = ContactForm()
    return render(request, "blog/contact.html", {"form": form})
@end

# blog/middleware.py
import time


class TimingMiddleware:
    """Adds an X-Response-Time header to every response."""

    def __init__(self, get_response):
        self.get_response = get_response          # runs once, at startup

    def __call__(self, request):
        start = time.perf_counter()               # before the view
        response = self.get_response(request)
        elapsed = (time.perf_counter() - start) * 1000
        response["X-Response-Time"] = f"{elapsed:.1f}ms"   # after the view
        return response

@module m24 | 🎤 | 24 · Interview | Module 24 — Interview Questions & Practice | Top questions · Short answers · Where to practise
@topic 🎤 Top Django Interview Questions
@table
Question | Short answer
What is MVT? | Model (data), View (logic), Template (presentation); Django's version of MVC
Project vs app? | A project is the whole site and settings; an app is a reusable feature
What is the ORM? | Python classes and methods that generate SQL for you
`null=True` vs `blank=True`? | Database may store NULL vs form may be left empty
What are migrations? | Version-controlled files that change the database schema
`select_related` vs `prefetch_related`? | JOIN for ForeignKey/OneToOne vs a separate query for many-to-many and reverse relations
`get()` vs `filter()`? | One object (raises errors if 0 or many) vs a QuerySet of any size
Why are QuerySets lazy? | They run SQL only when evaluated, so chaining is cheap
FBV vs CBV? | Functions give full control; classes reuse generic CRUD behaviour and mixins
What is middleware? | Hooks that process every request and response
What are signals? | Event hooks such as post_save that call receiver functions
How does CSRF protection work? | A secret token in each POST form is checked by middleware
Static vs media files? | Your own CSS/JS vs user uploads
How do you make a custom user model? | Subclass AbstractUser and set AUTH_USER_MODEL before the first migrate
What is DRF? | Django REST Framework: serializers, viewsets, routers, permissions for APIs
How do you deploy Django? | DEBUG off, env secrets, PostgreSQL, collectstatic + WhiteNoise, gunicorn, HTTPS
@end

@module m25 | 📋 | Quick Reference | Django Cheat Sheet | Project setup · ORM · Requests · Security · Tests
@topic Project Setup and Request Flow
@table
Need | Command or component
Create project | `django-admin startproject config .`
Create app | `python manage.py startapp catalog`
Route request | URLconf → view → response
Render HTML | `render(request, "catalog/list.html", context)`
Redirect by route name | `redirect("catalog:detail", pk=item.pk)`
Read setting | `settings.DEBUG` (use environment-specific settings)
@end
@topic Models and QuerySets
@table
Need | Pattern
Apply migrations | `python manage.py makemigrations` then `python manage.py migrate`
Filter records | `Product.objects.filter(is_active=True)`
Get one object | `get_object_or_404(Product, pk=pk)`
Join single-valued relation | `select_related("category")`
Prefetch collections | `prefetch_related("tags")`
Atomic writes | `with transaction.atomic(): ...`
Limit returned fields | `values("id", "name")` or `only("id", "name")`
@end
@topic Forms, Security, and Delivery
@table
Need | Pattern
Validate input | Use a Django Form or ModelForm and check `form.is_valid()`
Require login | `@login_required` or `LoginRequiredMixin`
Check authorization | Enforce object-level access in the server-side view/service
Protect POST forms | Include `{% csrf_token %}` in internal forms
Static assets | `static/` sources and `collectstatic` for deployment
User uploads | Store as media; validate type, size, and access separately
Test a request | `django.test.Client` or `TestCase` with assertions
@end
@warn Keep `DEBUG` off in production, keep secrets out of source control, validate permissions server-side, and use `get_user_model()` when code needs the configured user model.
